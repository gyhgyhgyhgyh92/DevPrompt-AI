## 3. 子阶段详设

### 6A · 契约冻结与后端补全（T6-2 + T6-9 + T6-11 后端）

**SMART 目标**：Specific=①GET+PUT `/settings` 端点落地（模型服务写本地设置文件、流程参数写 SQLite settings 表、密钥恒脱敏回显）②PUT `/preference` 与 GET `/history` 从 501/9004 转正 ③`app.openapi()` 导出管线跑通 ④structlog 固定事件名落地；Measurable=11 端点全部可独立调用、后端 pytest ≥257+新增全绿、openapi.json 可稳定导出、`X-Request-ID` 全端点透传；Achievable=service 层能力已就绪（preference_store.save / session store）；Relevant=6B 前端类型生成与 6F 设置中心的唯一契约输入；Time-bound=W1 内完成。

**步骤**：
1. **第一步**（执行 Agent）：定义 `/settings` Pydantic 契约——`SettingsResponse`/`SettingsUpdate`（模型服务：base_url、api_key **仅脱敏形态**、model_id、decider、timeout、temperature、max_tokens；流程参数：followup_soft_round_guard、followup_cost_budget、telemetry）。候选集上限 25 为宪法常量**不入 settings**，仅由锁定项只读下发。同步扩展 `AppConfig` 加载链 **env > 本地设置文件**（`settings.json`，0600 权限），并按真源 §13 批准记录修订宪法 MUST-19 措辞为「环境变量优先；密钥不入库、不进日志」（与三份配套文档同步）。
2. **第二步**：`routes.py`/`schemas.py` 落 GET+PUT `/settings` 薄壳（PUT 写设置文件 + SQLite 流程参数表）；PUT `/preference` 接 `preference_store.save`（含向量 clip01 校验）；GET `/history` 接 session store list（脱敏：不返回原句明文，仅 id/时间/state/项目名）。
3. **第三步**：structlog 接线（T6-9）：flow.started/completed、decider.switched、recommendation.made/skipped、state.truncated、followup.guardrail、followup.escaped、cache.hit/miss；测试断言生产 INFO 级不落盘原句与完整路径。
4. **第四步**：`scripts/export-openapi.py` + pytest 调 `app.openapi()` 导出 `openapi.json`（入库），验证两次导出 diff 为零（契约冻结证据）。
5. **第五步**：门禁（ruff/mypy/pytest/架构检查/契约冒烟）+ 提交 `feat(api)`。

**任务边界**：起=9 端点现状，止=11 端点契约冻结；**不改 `frontend/`**（尚不存在）；`openapi.generated.ts` 的实际生成在 6B 执行（本阶段只保证导出源稳定）；settings 前端 UI 归 6F。
**验收标准**：11 端点独立调用全通；PUT `/settings` 后密钥出现在设置文件且 **SQLite 与日志中无密钥**；GET 回显恒 `sk-••••` + 尾 4 位；PUT `/preference` 后 GET 返回更新值且超界值被 clip；`/history` 不含原句明文；openapi 两次导出 diff 为零。

### 6C · 状态管理与 API 层（T6-6）

**SMART 目标**：Specific=api 五文件（client/endpoints/interceptors/errors/types）+ 三 store（useOptimizeStore/usePreferenceStore/useSettingsStore）+ useSSE hook + 全响应 Zod 校验；Measurable=新增单测 ≥15 用例全绿（含 SSE cleanup 断言、畸形响应拒绝断言）；grep 无 `useStore(s => ({...}))` 违规形态；Achievable=契约已在 6A 冻结；Relevant=MUST-15/16 直接落点；Time-bound=W2 后半。

**步骤**：
1. **第一步** `api/`：client 统一信封解包（code=0 取 data；非 0 抛映射错误）、request_id 透传（`X-Request-ID`）、SSE 订阅封装、超时与中止。
2. **第二步** `schemas/`：手写 Zod（optimize/preference/settings/common），**必须与 openapi.generated.ts 对齐**（check:contract 保证）；校验失败不重试（契约破坏，MUST-15）。
3. **第三步** `useOptimizeStore`：流程快照、当前态、三套方案、ranking 视图；**SSE 消息在 store 内处理**；断流后由业务层显式决定（不自动重连）；恢复路径 = `GET /result/{flow_id}`（服务端权威）。
4. **第四步** `usePreferenceStore`（向量 + 采纳历史）与 `useSettingsStore`（后端设置 + localStorage 外观项，键前缀 `devprompt:v1:` + Zod 读取校验）。
5. **第五步** `useSSE`：EventSource 生命周期管理，**`close()` 写在 effect cleanup**（单测断言 unmount 后关闭）。
6. **第六步**：单测 + MUST-16 静态检查（多字段订阅 useShallow）+ 门禁 + 提交 `feat(web)`。

**任务边界**：不做任何 UI 组件；store 不 fetch（数据获取在 api/，store 只存结果）；不导出 action（从 hook 返回）。
**验收标准**：单测 ≥15 全绿；SSE unmount 关闭断言通过；畸形响应被 Zod 拒绝且不发起重试；无 MUST-16 违规形态。
