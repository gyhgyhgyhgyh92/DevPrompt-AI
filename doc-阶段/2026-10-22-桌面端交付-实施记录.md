## 3. 偏离与缺陷修正（留档以免后人重犯）

### ① PyInstaller 冻结态崩溃一：`importlib.metadata.version('mcp')`

`agents/mcp/_compat.py` 在**模块导入时**执行 `MCP_MAJOR_VERSION = _major_version("mcp")`，且无 try/except；
PyInstaller 默认不带 dist-info 元数据 → 冻结包一 import 就 `PackageNotFoundError`。
修法：`copy_metadata('mcp')`（另带 `openai-agents` 只为版本号准确——它的 `version.py` 本身有兜底）。

### ② PyInstaller 冻结态崩溃二：prompts/*.md 数据文件

`agents/sandbox/memory/prompts.py` 按 `Path(__file__).parent` 读 `prompts/memory_consolidation_prompt.md`；
PyInstaller 默认只收 `.py`。修法：`collect_data_files('agents')`。

> ①② 都是**仅冻结态暴露**的缺陷：开发态有源文件故不崩，构建成功也不代表能跑。
> 这正是 `smoke-sidecar.ps1` 存在的理由——必须实跑打包产物，不能只信构建退出码。

### ③ Inno 桌面图标在最低权限下拒绝访问

`{commondesktop}`（公共桌面）需管理员，`PrivilegesRequired=lowest` 时 `IPersistFile::Save` 报 `0x80070005`。
修法：改 `{userdesktop}`（每用户桌面）。

### ④ 放弃 electron-builder（偏离计划文字）

计划文字写了「electron-builder --dir + Inno」，实施时放弃该依赖：本项目不用它的 NSIS/Squirrel 目标
（安装器由 Inno 承担）、不签名、不自动更新——它只提供二进制 staging，而手工 staging 约 30 行 PowerShell
即可覆盖。少一个 26.x 重依赖更贴合 MUST-04。

### ⑤ pnpm 10 默认不执行依赖的安装脚本

`pnpm install` 后 `electron/dist/electron.exe` 不存在（Electron 二进制下载脚本被跳过），
且 `pnpm install` 因「已安装」不会补跑。修法：`package.json` 加 `pnpm.onlyBuiltDependencies: ["electron"]`，
首次装完后如需补跑用 `pnpm rebuild electron`。

### ⑥ staging 通配符自复制

`Copy-Item desktop\dist\* $appDir -Recurse` 把同目录下的 `stage/`、`sidecar-dist/` 一起复制进了
`resources\app`（dist 目录被构建产物污染）。修法：只收 `*.js` / `*.js.map`。

### ⑦ 冒烟脚本自身的假阳性

环境变量写进局部哈希表却没传给子进程（`Start-Process` 无 `-Env` 参数），rg 是靠兜底扫描通过的而非注入生效。
修法：改进程级环境变量传递，并在 finally 清理。

### ⑧ `/DIR` 参数被空格拆断

`Start-Process -ArgumentList "/DIR=D:\Works\DevPrompt AI\..."` 拼接后不加引号，Inno 只收到空格前的
`D:\Works\DevPrompt`，导致误装到该路径。修法：e2e 改为不传 `/DIR`、直接装到真实默认位置（更贴近用户实际）。

### ⑨ 网络：GitHub 不可达时的下载路径

winget 走 GitHub 报 `0x80072efd`；5 个 GitHub 镜像全部超时/500；本机无任何代理；CDP 代理亦不可用。
最终方案：DoH（`dns.google`）取 github.com 与 objects.githubusercontent.com 的 IP，
用 `curl --resolve <host>:443:<ip>` 下载官方 `innosetup-7.1.0-x64.exe`，
**先验签再安装**（`Get-AuthenticodeSignature` → Valid，发布者 `CN=Pyrsys B.V.`，即 Inno Setup 官方主体）。

## 4. 构建安全（PyInstaller 产物防杀软误报）

| 措施 | 状态 | 理由 |
|---|---|---|
| one-dir 而非 one-file | ✅ | one-file 启动向临时目录解压，行为特征接近 dropper |
| 禁用 UPX | ✅ | UPX 加壳是杀软重点启发式特征 |
| 版本资源元数据 | ✅ | sidecar exe 与安装器均嵌入 ProductName/Company/OriginalFilename（版本读 `pyproject.toml` 单一来源） |
| console 模式 | ✅ | sidecar 的 stdout 本就是协议通道；隐藏控制台反而增加可疑度 |
| 代码签名 | ❌ | 需购买证书，用户裁定不做（D5） |

**扫描验收方式（2026-10-25 定稿）**：开发机 Windows Defender 被显式关闭
（注册表 `HKLM\SOFTWARE\Microsoft\Windows Defender` 下 `DisableAntiSpyware=1`、
`DisableAntiVirus=1`，WinDefend 服务 Stopped、无签名版本），`MpCmdRun` 报
`WARN: Product/Feature disabled`，故**不用 Defender 做验收**（也不代改安全设置）。
本机实际在跑的 AV 是**腾讯电脑管家**（SecurityCenter2 注册项「腾讯电脑管家系统防护」，
进程 `QQPCRTP` / `QQPCTray`），改用它对产物做实测——更贴近本机真实环境。

待扫产物（含 SHA256 以便核对扫描对象）：

| 产物 | 大小 | SHA256 |
|---|---|---|
| `desktop/dist/installer/DevPromptAISetup-0.1.0.exe` | 138.7 MB | `0BC4717F8CF70C0A0327BFD3248405B448637C65ECA377F0880739D7D3AF5E33` |
| `desktop/dist/stage/resources/sidecar/devprompt-ai-desktop.exe` | 15.6 MB | `7C24237435BCC70A226C46E635409FCC072065B9CE9A79F6D9ED12C526A75555` |

**扫描结果（2026-10-25 实测）：两个产物均无风险。**

用腾讯电脑管家对上述两个文件逐个右键扫描，安装包与 sidecar exe 均报**「无风险」**，
未出现误报。至此四层防误报措施（one-dir / 禁 UPX / 版本资源元数据 / console 模式）
经本机实际在跑的 AV 验证有效。

**残余风险**：未做代码签名，首次运行会有 SmartScreen「未知发布方」提示（一次点击即过，
非木马判定）；将来拿到证书可经 `iscc --signtool` 消除，接入点只需改 `build-desktop.ps1` 一处。

> 若将来拿到代码签名证书，这一步的残余风险（SmartScreen 信誉提示）可一并消除：
> `iscc` 已支持 `--signtool`，只需在 `build-desktop.ps1` 的 iscc 调用处接入。
