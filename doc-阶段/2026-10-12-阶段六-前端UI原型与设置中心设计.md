### 1.2 各区要素与契约映射

| UI 元素 | 数据来源（后端字段） |
|---|---|
| 会话侧栏状态徽章 | 会话 state（`GET /history`，阶段六前本地留存） |
| 状态机步进器 | SSE `GET /progress/{flow_id}` 推送的 9 态（仅镜像渲染，MUST-07） |
| 用户原句气泡 / 已澄清 chips | `FlowSnapshot.session_id` + `cleared[]` + `questions[].key` |
| 三套方案卡 A/B/C | `FlowSnapshot.variants[]`（A 无行号 / B 边界 / C 行号+token 出处+测试指令） |
| 推荐徽章 + 原因文案 | `ranking.marked/reason/gap/confidence`——前端零阈值（MUST-08），标记与否完全由后端 `decide_mark` 决定 |
| fit/pref/total 指标条 | `ranking.fit/pref/total` |
| 反馈操作条 | `POST /feedback`（采纳/编辑后采纳/跳过 → L3 向量更新，F-603） |
| 目标定位 / 取证事实 | 检索定位与取证层结果（「LLM 决策 + ripgrep 精确取证」的界面化表达） |
| L3 偏好四维条 | `GET /preference` 向量（detail_level / include_diff / specify_tests / max_files_norm） |
| 状态栏 SSE 提示 | SSE `close()` 写在 effect cleanup，断流不自动重连（MUST-15） |

**组件落点**（T6-10 核对，命名以架构文档 §5.1 为唯一权威）：三栏工作台 = `SessionSidebar`（左栏，6D）/ 流程线程（`OptimizePage` 中栏）/ `ContextPanel`（右栏，6D）；步进 = `PhaseIndicator`；6E 八组件 = `OptimizeInput`/`PromptCard`/`VariantTabs`/`RecommendBadge`/`ScoreDetail`/`ConfidenceNotice`/`FollowupForm`/`CopyButton`；设置中心五组件 = `SettingsModal`/`ModelServicePanel`/`AppearancePanel`/`MemoryPanel`/`SecurityPanel`。

### 1.3 与现有页面规划的关系

- 本工作台是 **`OptimizePage`（`/`）的布局升级参照**：会话侧栏与上下文面板内嵌于主页面，三路由结构（`/`、`/history`、`/preference`）**不变**（T6-4）；侧栏项即路由入口。
- 组件命名继续以架构文档 §5.1 为唯一权威（T6-5/T6-10），本文只约束布局与交互形态。

## 二、反问态原型（ASKING）

- 步进器停在 ASKING（品牌色当前环），已完成态打勾。
- **澄清卡 ×N**：每张绑定一个未知项（MUST-26），四要素 = `key`（等宽徽章）+ `reason`（缺失原因）+ `best_guess`（当前最佳推断，可一键采用）+ 答复输入框。
- **逃生按钮常驻**：「直接生成（A 保守版 + 待确认清单）」→ `POST /followup/{flow_id}` escape 模式，埋点 `followup.escaped`。
- **软护栏横幅**：第 `FOLLOWUP_SOFT_ROUND_GUARD`(10) 轮触发时显示「继续追问 / 直接生成」裁决面板（guardrail_action 模式），不静默终止。
- 批量答复经 answers 模式一次提交；重复提交由按钮禁用防护（MUST-15，禁用时间戳去重）。

## 三、设置中心（F-604）

### 3.1 入口与形态

- 入口：标题栏右侧 **⚙ 设置** 按钮（「API 正常」状态旁），所有页面可见。
- 形态：**模态面板**（非路由页），左侧四项导航 + 右侧内容区，Esc/✕ 关闭。

### 3.2 四标签页规格

| 标签页 | 内容 | 持久化位置 |
|---|---|---|
| ⚙ 模型服务 | **模型列表管理**（2026-10-13 改版）：条目卡列表（显示名称/供应商/Base URL/模型 ID/API Key，密钥恒脱敏 `sk-••••3f7a`），每卡「设为当前」「删除」，底部「新增模型」；「设为当前」条目整条生效；下方保留全局调用参数（决策层/超时/温度/max_tokens）与「测试连接」 | 本地设置文件（`models` + `active_model_id`，经 GET/PUT `/settings`） |
| ◐ 通用外观 | 主题三态分段切换（浅色/深色/跟随系统，带缩略预览）、界面语言（English 计划中）、代码字体、启动恢复会话开关、桌面通知开关 | 前端 localStorage（`devprompt:v1:` 前缀 + Zod 读取校验） |
| ◈ 长期记忆 | L3 偏好四维滑条微调（PUT `/preference`）、更新规则与衰减系数 0.9 只读说明、采纳历史表格（时间/仓库·会话/档位/方式）、导出 JSON、清空采纳历史（danger 按钮；经 `DELETE /preference/adoptions` 服务端清空，双重确认后显示清空条数——D-6F-4 已关闭） | 复用 L3 双表（SQLite） |
| ⚑ 流程与安全 | 反问软护栏轮数与成本预算调节、候选集上限 25（**锁定只读**，标注「宪法 MUST-09 锁定」）、遥测开关、清除本地数据（会话 + 记忆，双重确认） | 流程参数经 PUT `/settings` 写 SQLite |

### 3.3 安全边界（MUST-19 口径澄清，随 T6-11 落地）

- API Key 存**本地设置文件**（非 SQLite、不进任何级别日志、界面回显恒脱敏）。
- `AppConfig` 加载链扩展为 **环境变量 > 本地设置文件**，环境变量保持最高优先级。
- 宪法 MUST-19 措辞**已修订落地**（2026-10-12，随 T6-11/6A）：「环境变量优先；密钥不入库、不进日志」，`AppConfig` 加载链为 env > 本地设置文件（settings.json 0600）——批准记录见真源 §13（附则：宪法变更已与三份配套文档同步）。
- 业务参数（护栏轮数、候选上限等）由后端下发渲染，前端零阈值常量（MUST-08）；锁定项在前端仅展示为只读。

## 四、契约变更摘要

- 端点契约：9 → **11**（新增 `GET /settings`、`PUT /settings`），随 T6-11 计入契约冒烟（T6-2 流程自动生成 TS 类型）。
- 组件清单（§5.1）：新增 `components/settings/` 五组件 + `ui/Toggle.tsx` + `ui/Slider.tsx` + `stores/useSettingsStore.ts` + `schemas/settings.ts`。
- 无新增第三方依赖（MUST-04）：主题切换用 CSS Variables + `data-theme`，滑条/开关为自研组件。

## 五、实施注意

| 宪法条目 | 落点 |
|---|---|
| MUST-07 | 步进器/状态徽章只镜像后端状态，转移逻辑唯一在 `state.py` |
| MUST-08 | 推荐标记、原因文案、锁定项值全部后端下发；前端 grep 不得出现 0.12/0.5/threshold |
| MUST-15 | SSE close 在 effect cleanup；`POST /optimize` 禁重试、按钮禁用防重复提交 |
| MUST-16 | 三个 store（optimize/preference/settings）；多字段订阅 `useShallow`；store 不 fetch |
| MUST-19 | 密钥脱敏回显；错误响应仅 code+message+request_id |

### 7.2 四项澄清裁定（AskUserQuestion 2026-10-12）

1. **图二蓝圈元素全移**（保留文件夹选择）。
2. **`GET /history` 后端增补 `title`**（custom_title 优先，否则原句截断 ≤40 字；旧数据回退空串由前端拼「项目 · 状态」）。
3. **菜单三项落后端**（置顶/重命名/删除各经 `PATCH`/`DELETE /history/{id}`）+ **复制项目路径**（Web 无「在资源管理器打开/文件管理/分享」能力，共保留 4 项视觉）。
4. **图五结构 + 方案组嵌入**（三套方案组重排进 AI 回复正文）。

### 7.3 与旧三栏方案的取代关系

- 旧 `OptimizePage` **三栏工作台**（`SessionSidebar` | 流程线程 | `ContextPanel`）→ 重构为**固定侧边栏（图三）+ 对话流主区（图五）**。
- `ContextPanel` 信息 → 融入 AI 回复正文的「上下文信息」小节；`PhaseIndicator` 步进器 → 融入回复块「耗时/状态折叠行」（状态转移逻辑仍唯一在后端 `state.py`，前端仅镜像，MUST-07）。
- 三路由结构（`/`、`/history`、`/preference`）不变；侧边栏项仍为路由入口。
- 默认**浅色主题**为第一视觉（对照参考图），深色主题保留经 ⚙ 设置切换。

### 8.1 调研结论 · 问题清单（22 项）

### 8.3 形态分支约定

- 判据：`api/nativeFolder.ts` 的 `isDesktopRuntime()`——preload 桥 `window.devpromptDesktop`
  的**存在性**，不做 UA / 平台嗅探；
- 外壳以 `data-shell="desktop" | "web"` 分支；桌面专属 chrome 只在桌面形态进 DOM；
- 跨模块的桌面专属覆写一律走 `[data-shell='desktop']` 属性钩子——CSS Modules 类名是哈希值，
  无法跨 module 用后代选择器命中；
- 桌面专属尺寸常量集中在 `styles/tokens.css` 的「桌面工作台尺寸」段，Web 形态的值不受影响。
