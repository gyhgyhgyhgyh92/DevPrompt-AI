**关键实现约定**：

- 缓存两级（符号表 TTL 1h、决策结果 TTL 30min），**决策结果缓存键必须含阈值配置 hash**，否则调阈值后读到旧结果

- Jev 决策实现在 F-202，W3 交付；无密钥自动降级 LLM 并记录原因

**W1 生死线（F-801）**：候选集召回率 ≥80% 且排序准确率 ≥80%（≥3 个真实仓库 × 10 条原句，人工标注）。未达标不得进 W2，需重新论证价值主张。

**已核实的关键事实（后续引用以此为准）**：

1. **Jev 未开源且仍在 waitlist**。权重/训练代码/服务端实现全部未公开，无 HuggingFace 仓库。仅 Python/JS SDK 与 Agent Skills 为 MIT。唯一路径是官方 API 申请。模型 `jev-1.13.0`，别名 `jev-latest`（会漂移，须钉版本号）。限额 64k 请求 / 32k state，100K tok/s，80 req/s。$0.042/Mtok，output 免费。开源替代：Convai **Laya**（Apache 2.0，322–421M，单 GPU），但不微调准确率接近随机。

2. **Jev + grep 顺序不可颠倒**。state 上限 32k，大型项目压缩后仍超限，官方明确警告 state 越长准确率越低。必须 ripgrep 先压到 ≤25 条候选（仅含符号名+路径），Jev 再排序。Jev 是裁判不是检索器。

3. **OpenAI Agents SDK 定为 harness 底座，CrewAI 淘汰**。CrewAI 缺 Session 抽象、Guardrail、Tracing。三个坑：① `AgentLoop` 只是架构概念非公开类，只能用 `Runner`；② 第三方 provider 必须 `set_default_openai_api("chat_completions")`；③ 第三方 key 走 OpenAI tracing 会 401，必须 `set_tracing_disabled(True)`。多模型用 `set_default_openai_client()` + `LitellmModel`（官方标注 beta/best-effort）。

4. **Qoder SDK 不可集成**。`qoder-agent-sdk` 1.0.15 为 Other/Proprietary 许可，运行机制是启动 `qodercli` 子进程转发 Qoder 云端 → 与「私有代码不上云」定位冲突。仅作设计参照（其四维度增强框架：需求明确化/场景上下文化/约束完善化/结构化输出）。

5. **推荐阈值 0.5 在归一化尺度下失效**（本轮新发现）。因 `Δ = 0.6×Δ适配度 + 0.4×Δ偏好`，而偏好匹配度值域 [0,1] 最大分差仅 0.4 < 0.5，即使适配度完全同分也永不触发。已提出双阈值方案 C（硬 0.5 保留 + 软 0.12 拦截），待用户确认。
