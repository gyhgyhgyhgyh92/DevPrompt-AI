# 候选带签名的排序收益上界（离线归因，零 LLM 调用）

数据源：`eval/recall/report-ranking-2026-10-11-real.json`（F-801 第二段唯一有效的排序实测）

## 结论速览

| 口径 | 值 | 含义 |
| --- | --- | --- |
| 实测命中率 | 58/100 = 58.0% | 历史基线（2026-10-11） |
| 排序天花板 | 95/100 = 95.0% | 目标进入候选集的比例，排序侧无法突破 |
| 候选歧义率 | 27/100 = 27.0% | top5 内存在同名候选（签名有判别力的范围） |
| 签名可挽回上界 | 1 条 | 排错且 top1 与目标同名不同路径 |
| 签名无能为力 | 41 条 | 排错且 top1 与目标不同名 |
| 挽回后命中率上界 | 59.0% | 乐观假设：签名让模型在歧义 case 上一律改判 |

## 怎么读这组数

1. **排序侧的空间由召回决定，不由排序决定**：目标没进候选集的 case，排序层怎么排都命中不了。
2. **签名只在同名歧义处有判别力**：其余错误里 top1 与目标根本不同名，签名提供不了判别信息。
3. 于是「签名最多能挽回多少」是一个**有界且很小**的量，与供应商额度无关。

## 对 W3 决策的影响

- 签名改造**保留**：零额外 LLM 调用、零额外进程，W1 已证不损害召回（95/100 未退化）；回退成本同样为零（ctags 不吐 signature 字段即自动降级）。
- 「签名是否提升排序准确率」在**没有额度时不再是待决项**：收益上界已被离线量化，其不确定性只影响上界内的几个百分点，不影响任何门禁（MUST-25 第二段自 2026-10-15 起是参考指标）。
- 若将来有额度再跑 A/B（带/无签名各 100 例），判读标准沿用既有文档：error 率相近（<5%）时命中率差值才可归因于签名本身。

## 本方法的限制（必须一并读）

1. 上界是**乐观**的：假设模型见到签名就一定改判，实际收益只会更低。
2. 歧义判定基于 top5 明细，top5 之外的同名候选未覆盖 → 歧义率是下界。
3. 归因基于**无签名**时期的排序结果，不能反推「加签名后模型会怎么排」——它给上限，不能替代实测。
