判据：是否像真实开发者会写的**模糊需求**（含中英混合），而非"教科书式命题"或"AI 生成的抽象描述"。

### 逐仓抽样论证（每仓抽 4 条说明通过理由）

**click**（中文口语化 + 库名简称，典型真实提问）
- `click 的 echo 输出 json 时不要转义中文` — 带库限定词、具体到 `echo`、诉求是行为而非实现，真实用户会这么写。
- `secho 同时传 fg 和 nl 时输出顺序不对` — 直接点名两个参数名并描述 bug 现象，典型 issue 描述。
- `CliRunner 混合 stdout stderr 的捕获顺序不稳定` — 描述可复现的异常行为，真实测试场景。
- `getchar 在 Windows 下也要响应 Ctrl+C` — 平台差异诉求，真实跨平台需求。

**requests**
- `requests.post 上传文件的 filename 中文编码有问题` — 中文编码 bug，真实用户高频问题。
- `状态码4xx 5xx 时报错信息带上响应体摘要` — 改进诉求而非 API 设计，真实。
- `Session 会话对象在 close 之后复用要给警告` — 描述生命周期误用，真实。

**pinia**
- `storeToRefs 解构 getters 后失去响应式` — 典型 pinia 用户踩坑，真实。
- `$patch 传回调函数时支持异步分批修改` — 用 `$` API 名，真实用户熟悉内部 API 才会这么说。
- `setActivePinia 在应用卸载时还原成 undefined` — 精确到函数名，真实。

**axios**
- `mergeConfig 对 headers 的合并策略按请求方法区分` — 精确到内部函数，真实 contributor 视角。
- `AxiosHeaders 的 set 支持传对象批量设置` — 真实 API 增强诉求。
- `嵌套对象序列化成表单数据时限制深度` — 真实工程约束（防原型污染/性能）。

**headlessui**
- `复选框的点击热区扩大到整行` — 纯 UI 体感需求，产品/前端真实说法。
- `弹窗打开时禁止背景滚动` — 经典需求，真实。
- `菜单打开时按 ESC 关闭并把焦点还给触发按钮` — 含可访问性语义，真实。

**整体判断**：100 条原句全部通过。特征上呈现真实分布——**中文为主、夹英文标识符、诉求描述行为而非实现、包含 bug 现象与产品体感**。

## 附录：审查过程中修正的自身工具缺陷

| 缺陷 | 现象 | 修正 |
|---|---|---|
| `Path.parents[3]` | 路径多退一级，读到 `D:\` | 改为 `parents[1]` |
| `git grep -E` + lookbehind | Git ERE 不支持 `(?<!\w)`，导致 100/100 误报「仓库内找不到符号」 | 改用 `-F` 固定串 + Python 侧词边界过滤 |
| TS 泛型签名未覆盖 | `export function skipHydrate<T = any>(` 未匹配，误报 12 条 | 正则加 `(?:<[^>]*>)?` |
| 以「首个命中文件」判路径 | 判据本身错误（git grep 顺序与标注无关） | 改为「`expected_path` 是否在命中文件集合内」 |
| `SymbolTableResult.table` | 字段名实为 `symbols` | 已修正 |
| `SymbolTableProvider()` | 必填 `runner` 参数 | 注入 `LocalCommandRunner()` |

> 这些是我审查脚本的缺陷，**与标注数据无关**，但必须记录：否则会得出「100 条全部符号不存在」的错误结论。
