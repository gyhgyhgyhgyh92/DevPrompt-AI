## 六、缺陷清单（仅报告）

### D-01 · P1 · Trace 多轮事件台账按全局 seq 排序，轮次交错

- 影响：同一会话两轮以上时，事件列表把 turn0/turn1 交错返回；按 seq 分页的轮次顺序不稳定，人类回溯体验下降。
- 复现：`uv run pytest tests/e2e/obs/test_obs_trace.py::test_tr04_multi_turn_pagination_is_turn_major -q`
- 建议：query_events 改为 ORDER BY turn_index, seq；cursor 改为 (turn_index, seq) 复合游标，并同步调整 API 契约与前端加载更早逻辑。
- 状态：fixed（2026-11-14，回归用例已覆盖）

### D-02 · P0 · trace.write_failed 未登记事件名，写失败时二次抛错破坏 fail-open

- 影响：TraceCollectorImpl.flush 的异常分支调用 emit('trace.write_failed')，该事件不在 EVENT_NAMES，emit 抛 ValueError；当缓冲区在轮次中途写满时异常穿透到业务，Trace 写失败会直接导致本轮优化失败。
- 复现：`uv run pytest tests/e2e/obs/test_obs_resilience.py::test_ab06_trace_write_failure_keeps_business -q`
- 建议：① 在 observability/logging.EVENT_NAMES 登记 trace.write_failed；② flush 的 except 分支整体 try/except 包裹 emit，确保观测失败永不外抛。
- 状态：fixed（2026-11-14，回归用例已覆盖）

### D-03 · P1 · 并发告警评估触发唯一索引冲突

- 影响：MetricsService.evaluate 并发（多轮/多会话同时结束）时，sync_alerts 先查后插无事务保护，触发 metrics_alerts 唯一索引 IntegrityError。
- 复现：`uv run pytest tests/e2e/obs/test_obs_metrics.py::test_mt04_concurrent_evaluation_is_idempotent -q`
- 建议：sync_alerts 使用 BEGIN IMMEDIATE 单事务 + INSERT ... ON CONFLICT DO UPDATE，或对同一 scope 加进程内串行锁。
- 状态：fixed（2026-11-14，回归用例已覆盖）

### D-04 · P0 · POST /runs 不接受前端新生成的 session_id，新会话直接 6003

- 影响：前端 OptimizePage 在新会话时用 crypto.randomUUID() 生成 session_id 并 POST /runs；RunManager 交给 service.optimize(start_turn) 时该会话不存在，返回 6003（流程 ID 不存在），新会话无法通过多端运行协议启动。本次真实场景改用测试预建会话才跑通。
- 复现：`用任意新 UUID POST /api/v1/runs 后订阅 /sessions/{id}/stream：第二条事件即为 error code=6003。`
- 建议：RunManager.start 在会话不存在时创建容器（或新增 POST /sessions 供前端先建会话），并补充新会话经 /runs 启动的回归用例。
- 状态：fixed（2026-11-14，回归用例已覆盖）

### D-06 · P1 · 真实 LLM 调用的 token 用量未进入 Trace/Metrics

- 影响：真实运行中 llm.response 节点的 attributes.tokens 恒为 0，导致 Metrics 的 token_total/token_budget 规则失效，成本类指标不可用。
- 复现：`uv run python scripts/obs_e2e.py --real-llm；查看 RL-01 证据中的 llm_tokens 与 Trace 的 llm.response.attributes.tokens。`
- 建议：在 LLMGenerator 的调用链上确认 agent Runner 是否返回 usage；缺失时从共享 usage 聚合器（common.cost）回填到 Trace 事件属性。
- 状态：fixed（2026-11-14，回归用例已覆盖）

### D-07 · P1 · 真实 Trace 回放出现节点顺序漂移（47 matched / 2 mismatched）

- 影响：真实运行中 verify_facts 用 asyncio.gather 并发发起多路读取，事件 seq 取决于完成顺序；回放时并发完成顺序不同，导致 file.read/read 与 exists 错位，verify 结果为 diverged，无法作为严格回归基线。
- 复现：`uv run python scripts/obs_e2e.py --real-llm；查看 RP-02（XFAIL）与 eval/obs/runs/<timestamp>/success/devprompt.db 的 replay_nodes diff。`
- 建议：对并发取证按固定 key（工具参数/路径）排序后再分配 seq，或在比对时按 (kind, name, call_key) 对齐而不是按位置对齐。
- 状态：fixed（2026-11-14，回归用例已覆盖）

### D-08 · P1 · 真实 LLM 供应商余额耗尽，重复回归与多轮验证受阻（外部依赖）

- 影响：本次首个真实单轮成功（66 个 Trace 节点）后，DeepSeek/MiniMax/Kimi 三个已配置供应商均返回 402/429（余额不足或账号停用），后续真实多轮与重复验证无法完成。

- 建议：为测试环境准备独立且有余量的密钥；报告中保留历史成功证据，余额恢复后按同一命令复跑以补齐多轮场景。
- 状态：open（仅报告）

### D-05 · P2 · Session Log 仅覆盖 /runs 链路，/optimize 不写 run_events

- 影响：直接调用 POST /optimize（旧入口/脚本）产生的会话没有 Session Log 数据，与「全量日志」预期不一致。

- 建议：统一入口：/optimize 也注入 EventSink，或在文档与 UI 明确 Session Log 仅适用于 /runs 运行。

## 七、风险评估

- **P0 写失败二次抛错**：Trace 写异常会穿透业务，属于可观测性反向影响可用性，建议优先修复。
- **P1 并发告警冲突**：多会话同时结束可能丢失告警评估，影响指标可信度。
- **P1 多轮台账交错**：只影响回溯可读性与分页稳定性，不影响数据完整性。
- **P1 真实回放顺序漂移**：并发取证事件顺序不稳定，严格回归会误报 diverged。
- **P1 token 用量为 0**：Metrics 成本指标与 token 预算告警当前不可用。
- **P1 供应商余额耗尽（外部）**：真实 LLM 多轮与重复回归暂时不可执行。
- **数据隔离**：本次全部使用临时 DB；未修改用户真实数据库与 settings。

## 八、优化建议

1. 修复 D-02，并为所有 emit 调用加“事件名登记”单测门禁。
2. 修复 D-03，采用单事务 upsert，并在高并发用例中保留回归。
3. 修复 D-01 的排序与复合游标，前端 Trace 台账增加轮次分组。
