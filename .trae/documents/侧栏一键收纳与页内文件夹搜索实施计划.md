## 一、Summary

两项改造：
1. **侧边栏头部**（图一，[ProjectSidebar.tsx](file:///d:/Works/DevPrompt%20AI/frontend/src/components/history/ProjectSidebar.tsx#L303-L330)）：「项目 ⌄」的 **⌄ 箭头替换为【一键收纳】按钮**（点击收起整个侧边栏，主区撑满；标题栏 ☰ 恢复）；**彻底移除排序（↓↑）、筛选（≡）两个图标按钮**及其全部状态（`sortMode`/`isGrouped`）、事件绑定、两模式排序分支与 SVG 组件（`SortIcon`/`FilterIcon`），无残留冗余代码。
2. **页内文件夹选择器**（图二，[FolderPickerModal.tsx](file:///d:/Works/DevPrompt%20AI/frontend/src/components/optimize/FolderPickerModal.tsx)）：地址栏同行右侧新增**搜索框**，参考 Win11 资源管理器——实时输入响应（防抖 250ms）、**递归搜索当前文件夹子树**（后端提供）、结果含相对路径提示、范围控制（驱动器列表态禁用）、打开结果即退出搜索。

**最小改动约束**：不新增依赖；**不新增契约路径**（仅在既有 `GET /project/browse` 上加可选 `q` 参数 + 条目加一个字段 → 计数仍 13 路径/16 操作）；不动 store 架构（收纳状态就地存 App.tsx）；排序能力保留为单一既定顺序（不引入新排序 UI）。

**明确不做**：不恢复排序/筛选 UI（不引入替代控件）；不做搜索历史/高级语法/通配符；不做跨盘搜索（`path` 为空即驱动器列表态，不可搜）；搜索不返回文件（沿用「选择文件夹」语义，条目仍仅目录）。

## 三、Proposed Changes（按执行顺序）

### 阶段 A · 后端：递归搜索（harness + 契约）

**A1. `src/devprompt_ai/harness/browse.py`**
- `BrowseEntry` 增 `rel_parent: str | None = None`（相对基准目录的父路径；普通列举为 None）。
- 新增常量：`MAX_SEARCH_DEPTH = 6`（递归层数上限）、`MAX_SEARCH_NODES = 20000`（访问目录数上限，防跑飞）。
- 新增 `_iter_search_matches(root: str, query: str) -> tuple[list[BrowseEntry], bool]`：
  - 迭代遍历 `root` 子树（仅目录；文件跳过）；逐目录 `os.scandir`，单条目 `OSError` 跳过（沿用既有防御）；
  - 命中规则：目录名 `casefold()` **包含**查询串（trim 后）→ 生成条目，`rel_parent` = 该目录父目录相对 `root` 的路径（直接子级为 `""`，更深为 `a\b` 形式）；
  - 上限：命中数达 `MAX_BROWSE_ENTRIES` 或访问节点数达 `MAX_SEARCH_NODES` 或深度达 `MAX_SEARCH_DEPTH` → 停止并置 truncated=True；
  - 排序：`(深度, rel_parent.casefold(), name.casefold())`（浅层优先、同层按路径再按名）。
- `list_subdirectories(path, query="")`：`query.strip()` 非空 → `_iter_search_matches`；否则维持现有一级列举。搜索结果响应中 `path` 仍为**基准目录**（搜索范围不随结果漂移）、`parent` 沿用 `_parent_of(root)`。

**A2. `interfaces/api/schemas.py`** — `BrowseEntryPayload` 增 `rel_parent: str | None`（无默认值，沿用既有注释约定）。

**A3. `interfaces/api/routes.py`** — 路由签名加 `q: str = ""`；映射处补 `rel_parent=e.rel_parent`；docstring 注明「q 非空=当前目录子树递归搜索」。

**A4. `service.py`** — `browse_directory(self, path: str, query: str = "")` → 透传 query（空 path 时忽略 query 返回驱动器列表；同步 docstring）。

**A5.** `uv run --no-sync python scripts/export-openapi.py`（路径/操作计数不变）。

### 阶段 E · 前端：页内文件夹搜索（图二）

**E1. `FolderPickerModal.tsx`**
- 工具行结构：`← → ↑` + 面包屑（原有）+ **搜索区**（新增，右侧）：
  ```tsx
  <div className="folder-picker__search">
    <SearchIcon />
    <input className="folder-picker__search-input" aria-label="搜索当前文件夹"
           placeholder="搜索" value={query}
           disabled={listing === null || listing.path === ''}
           onChange={(e) => setQuery(e.currentTarget.value)}
           onKeyDown={(e) => { if (e.key === 'Escape') { e.stopPropagation(); setQuery('') } }} />
    {query !== '' ? <button type="button" className="folder-picker__search-clear" aria-label="清除搜索" onClick={() => setQuery('')}>✕</button> : null}
  </div>
  ```
- 状态与响应：`query`（输入值）+ `debouncedQuery`（250ms 防抖，`useEffect` + `setTimeout` 清理）+ 复用既有 `isLoading`。
- 搜索加载：`debouncedQuery.trim() !== '' && basePath !== ''` → `getBrowse(basePath, debouncedQuery)`；`basePath` = 进入搜索前的当前目录（即 `listing.path`，因搜索结果响应 `path` 仍返回基准目录，**范围不漂移**）。
- 搜索模式判定：`const isSearchMode = debouncedQuery.trim() !== ''`；列表渲染同一套行组件，搜索结果行**额外显示 `rel_parent`**（`.folder-picker__item-rel`，`rel_parent` 为空串则不显示）。
- 范围控制与交互：
  - `listing.path === ''`（驱动器列表）→ 搜索输入禁用（placeholder 仍「搜索」）；
  - **退出搜索**：导航类动作（双击/Enter 进入、返回上级、后退/前进、面包屑跳转）先 `setQuery('')` 再执行既有导航；
  - 双击搜索结果 → 进入该目录并清空搜索（Win11 行为）；单文件行不存在（仅目录）；
  - 状态栏：搜索态显示「N 个搜索结果」；`truncated` 提示改为「结果过多，仅显示前 500 项」（非搜索态沿用「目录过大，仅显示部分子文件夹」）。
- 空态文案：搜索态无结果 → 「未找到匹配的文件夹」。
- 顶部注释同步（新增搜索能力说明）。

**E2. `FolderPickerModal.css`** — 新增 `.folder-picker__search`（右侧、`flex`、`margin-inline-start:auto`、max-inline-size 220px）、`.folder-picker__search-input`、`.folder-picker__search-clear`、`.folder-picker__item-rel`（小字 `--color-text-muted`）；全部引用既有 token；≤480 窄屏：隐藏 `rel_parent` 提示并可让搜索框收缩（沿用既有断点块）。
