## 一、摘要

当前“模型选择”面板中的两个参数完成度不同：

| 参数 | 当前状态 | 目标状态 |
|---|---|---|
| 思考强度 `reasoning_effort` | 已保存、已在结构化调用经 `extra_body` 下发；但探针工具调用、Anthropic/Gemini 原生适配器不生效；多模型主备会继承激活条目参数 | 所有调用路径按模型能力下发；原生供应商映射为 thinking budget；按实际候选条目取参数 |
| 上下文长度 `max_context_length` | 只保存、展示、计算生效窗口；压缩与请求预算固定用全局 `context_window_tokens=1M`；告警函数无生产调用点 | 作为该模型的运行时窗口，驱动请求预算、压缩阈值与超窗重试；不向供应商发送非标准字段；不硬截断本轮取证 |

**不改运行时架构**：不引入四个 SDK，不替换 openai-agents，不新增第三方依赖。

## 二、四个 SDK 的调研结论

调研日期：2026-11-10。结论：**四者都不是可直接调用的模型客户端**，无法“整包迁移”；可复用的是它们成熟的**控制面参数语义**。

| SDK | 形态 | 思考强度实现 | 上下文长度实现 | 可否迁移 |
|---|---|---|---|---|
| **Codex SDK**（`@openai/codex-sdk` 0.161.0） | Node 包，spawn `codex` CLI，JSONL 事件 | Codex config `model_reasoning_effort`（low/medium/high/xhigh/max/ultra），经 `new Codex({config})` 或 `--config` 传入 | Codex config `model_context_window`（token 数），超出时由 Codex 自动截断历史 | ❌ 子进程 CLI，替换整个运行时 |
| **Trae** | 无公开 SDK，仅 IDE/企业版设置 | “Thinking Mode”：开 / 关 / 跟随模型默认；无显式 effort 枚举 | “Context Window (Token)”：可选预设或手填输入/输出上限；Max 模式 200K→1M | ❌ 无 SDK 可迁 |
| **CodeBuddy SDK**（`@tencent-ai/agent-sdk`） | Node 包，包装 CodeBuddy CLI | `SessionOptions.effort: low/medium/high/xhigh`；`thinking: {type: adaptive \| enabled(budgetTokens) \| disabled}`；`maxThinkingTokens` 已废弃 | 文档以 `maxInputTokens` / auto-compact window 表达；无统一 `context_window` 请求字段 | ❌ 需 CLI 与认证，替换运行时 |
| **Qoder SDK**（`@qoder-ai/qoder-agent-sdk` / Python） | 包装 `qodercli` 子进程；另有 Cloud Agents HTTP API | CLI：`resolveModel` 返回 `parameters.reasoningEffort`；Cloud：`model.effort`（none/low/medium/high/xhigh/max） | CLI：`parameters.contextWindow`；Cloud：`model.context_window`，取值来自模型 `available_context_windows` | ❌ proprietary + 子进程；仅作设计参照 |

### 可复用的成熟语义

1. **effort 是枚举，不是自由文本**；必须按模型能力位登记可选值，未登记不展示、不下发。
2. **窗口是“模型可选档位”**，取值必须来自该模型合法集合；不是任意正整数。
3. **关闭思考要显式表达**：Codex/Qoder 用 `none`，CodeBuddy 用 `thinking.type=disabled`；单纯“不发字段”等于跟随供应商默认，不等于关闭。
4. **窗口超限的正确行为是压缩历史**（Codex 自动截断历史、CodeBuddy auto-compact），不是静默丢证据。
5. **参数按模型粒度独立**：Qoder 的 `resolveModel` 每次请求返回该模型参数；CodeBuddy/Codex 也是按模型配置。

本计划即移植以上五条语义，不复制其代码。

## 四、目标行为定义（决策完成）

### 4.1 思考强度语义

| `api_mode` | 下发形态 | 说明 |
|---|---|---|
| `chat_completions` | `extra_body={"reasoning_effort": <effort>}` | OpenAI / DeepSeek / 兼容端点 |
| `responses` | `extra_body={"reasoning": {"effort": <effort>}}` | OpenAI Responses 的官方字段形状 |
| `anthropic_messages` | `thinking={"type":"enabled","budget_tokens":N}`；关闭时 `{"type":"disabled"}` | 由 Anthropic 原生适配器读取内部 effort 后构造；不把 `reasoning_effort` 透传给 Anthropic |
| `gemini_generate_content` | `thinking_config=ThinkingConfig(thinking_budget=N)` | 由 Gemini 原生适配器构造；`none` → `0` |

- **空值语义**：`reasoning_effort=""` 表示“未显式选择”。
  - 若该模型登记了 `none`（如 DeepSeek）→ 解析为 `"none"`，**真正关闭**；
  - 若未登记 `none` → 保持空，不下发，跟随供应商默认。
- **非法值**：写入时整单拒绝（见 §5）；运行时遇到非法值只忽略并记 `llm.request_params` 事件，不把 400 抛给用户。
- **多模型主备**：参数取**实际被选中的候选条目**，不继承激活条目。

### 4.2 上下文长度语义

- `runtime_window = cfg.max_context_length if > 0 else cfg.context_window_tokens`。
- 该窗口用于：
  1. `_assert_request_budget`（请求级输入预算）；
  2. `_assemble_context` 的 `plan_compaction` 与 `build_context`；
  3. `_maybe_llm_digest` 的压缩判定；
  4. 生成超窗后的“压一次重发一次”。
- **不向供应商发送窗口字段**：OpenAI/DeepSeek/Anthropic/Gemini 均无标准的“本次请求窗口”参数；强行发送会 400。
- **不硬截断本轮取证**：`current` 层仍然永不裁；窗口只影响历史层预算与是否触发压缩。若“system + current”本身超过窗口，抛出可操作错误（见 §5），而不是静默丢证据（MUST-25）。

### 4.3 关闭思考的 UI 语义

- `ModelPicker` 的强度按钮列表**过滤 `none`**（不把“none”当成一个强度按钮）。
- 开关关闭 → 仍写 `reasoning_effort: ''`；后端按 §4.1 解析：
  - DeepSeek（登记了 `none`）→ 发 `none`；
  - 其它模型 → 不发。
- 开关打开 → 沿用当前逻辑：已选值 → 官方默认档 → 第一档。
- UI 文案明确“关闭 = 显式关闭（若模型支持），否则跟随模型默认”。

## 五、实现改动

### 5.1 新增 `src/devprompt_ai/domain/model/tuning.py`

纯领域模块，零 I/O（MUST-06），只做参数归一与映射：

```python
CANONICAL_EFFORTS = ("none", "minimal", "low", "medium", "high", "xhigh", "max")

ANTHROPIC_THINKING_BUDGET = {
    "none": None, "minimal": 1024, "low": 2048, "medium": 8192,
    "high": 16384, "xhigh": 24576, "max": 32768,
}
GEMINI_THINKING_BUDGET = {
    "none": 0, "minimal": 512, "low": 1024, "medium": 4096,
    "high": 8192, "xhigh": 16384, "max": 24576,
}

def resolve_effort(raw: str, allowed: Sequence[str]) -> str | None:
    """空值 → 'none'（仅当 allowed 含 none）；非法值 → None；合法值原样返回。"""

def anthropic_thinking(effort: str, max_tokens: int) -> dict[str, object]:
    """返回 Anthropic thinking 字段；budget 夹到 max_tokens-1，不足则 disabled。"""

def gemini_thinking(effort: str) -> int:
    """返回 thinking_budget；未知 effort 返回 0。"""
```

- 所有映射常量集中在此，避免 `service`、`adapters` 各写一份。

## 六、参数校验与异常边界

| 场景 | 行为 | 错误/事件 |
|---|---|---|
| `reasoning_effort` 不在模型合法集合 | 写入时整单拒绝；运行时忽略 | 400 / `ConfigurationError`；运行时 `llm.request_params` 记空值 |
| `max_context_length` 不在合法档位 | 写入时整单拒绝 | 400 / `ConfigurationError` |
| 模型未登记 effort，但用户传了非空值 | 写入时拒绝（静态/动态都查不到） | 400 |
| 空 effort + 模型登记 `none` | 解析为 `none`，显式关闭 | `llm.request_params` 记 `none` |
| 空 effort + 模型未登记 `none` | 不下发，跟随供应商默认 | `llm.request_params` 记 `""` |
| `responses` 形态 | 发 `reasoning: {effort}` | 不重复发顶层字段 |
| Anthropic budget ≥ max_tokens | 夹到 `max_tokens-1`；仍不足则 disabled | `llm.request_params` 记实际预算 |
| Gemini 模型不支持 thinking | 仅当模型登记了 effort 才设置 | 未登记 → 不发 |
| 请求估算 > 所选窗口（生成） | `RequestBudgetError` → shrink 一次重发 | `context.overflow_retry` |
| 请求估算 > 所选窗口（探针/排序/调度） | 转 `DevPromptError(3003)`，给出“调大窗口/缩小范围”建议 | 3003 |
| 本轮 current 层单独超窗 | 不截断；按 3003 或生成超窗路径处理 | 不静默丢证据（MUST-25） |
| 多模型主备切换 | 每个候选使用自己的 effort/window | 候选级 `llm.request_params` |

## 九、假设与决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | 不引入四个 SDK 依赖 | 均为 Agent CLI 封装，不是模型客户端；引入会替换运行时，违反现有架构与本地优先定位 |
| 2 | 窗口只驱动本地预算/压缩，不发给供应商 | OpenAI/DeepSeek/Anthropic/Gemini 无标准请求窗口字段；Qoder Cloud 的 `context_window` 是其私有 API，不能类推 |
| 3 | 不硬截断 current 层 | MUST-25：截断证据会削弱召回率；超窗应压缩历史或报可操作错误 |
| 4 | 空 effort 在登记了 `none` 的模型上解析为 `none` | 让“关闭思考模式”真正生效；未登记 `none` 的模型保持“跟随默认”，不猜测 |
| 5 | Anthropic/Gemini 用 budget token 映射 | 两者没有 `reasoning_effort` 顶层字段；budget 是官方支持的等价控制面 |
| 6 | 多模型主备按候选条目取参数 | 参数是模型能力的一部分；继承激活条目会把不支持的参数发给备用模型 |
| 7 | 写入时严格校验，运行时容错忽略 | 用户输入边界必须拦住；运行时不能因配置脏数据把 400 抛给终端用户 |
| 8 | 新增 `llm.request_params` 事件，不记录 prompt/密钥 | 满足“参数真实传递”的可验证性，同时遵守 MUST-19 |

## 十、风险与回滚

| 风险 | 缓解 |
|---|---|
| Anthropic thinking 与 temperature 冲突 | 启用 thinking 时省略 temperature/top_p；budget 夹到 max_tokens-1 |
| Gemini thinking budget 因模型而异 | 只在模型登记 effort 时设置；未登记不发 |
| 小窗口导致频繁压缩/生成失败 | 保留 `context.overflow_retry`；错误文案给出“调大窗口/缩小范围”；1M 仍为未登记时的默认 |
| 多模型主备窗口不一致 | 候选级 budget 断言；失败按既有 `_FAILOVER_CODES` 切换 |
| DeepSeek 增加 `none` 改变 UI 选项 | 前端过滤 `none`，只作为关闭语义；单测锁定 |
| 文档/契约漂移 | 同步架构 §4.8、F-604；`check_architecture.py` 与 openapi 契约门禁 |

回滚：本次改动集中在 `domain/model/tuning.py`、`config.py`、`harness/llm.py`、两个原生适配器、`service.py` 与 `ModelPicker.tsx`；按文件回退即可，无存储格式变更。
