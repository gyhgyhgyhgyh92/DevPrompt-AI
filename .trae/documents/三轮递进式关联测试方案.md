## 三、指标定义（均为确定性计算）

### M1 · 准确率（5 项规则清单，等权 0/1）

判分对象：`variants` 中被推荐的那套；无推荐时取最高档（C > B > A）。

| 编号 | 判定项 | 判定式 |
|---|---|---|
| A1 | 定位文件正确 | `snapshot.target.path == "task/task-front/src/pages/bookManage/BookListPage.tsx"` |
| A2 | 组件与属性正确 | `body` 同时包含 `PageContainer` 与 `extra` |
| A3 | 变更代码正确 | 见下方逐轮期望 |
| A4 | 令牌引用正确 | `body + changes` 含 `antdTheme` 或 `#ff4d4f`（R2/R3 另接受 `#faad14` / `colorWarning`） |
| A5 | 四段式完整 | `body` 同时含 `## 一、` `## 二、` `## 三、` `## 四、` |

逐轮 A3 期望：
- R1：同时出现 `primary` 与 `danger`
- R2：同时出现 `danger` 与（`warning` 或 `colorWarning`）
- R3：同时出现 `openEdit`（或「编辑」）与 warning 系色值

**准确率 = 通过项数 / 5 × 100%**

### M2 · 单轮耗时

| 分量 | 取法 |
|---|---|
| T总 | `perf_counter()` 包住整轮（含可能的 followup） |
| T模型 | `snapshot.agent_elapsed_ms` |
| tokens | `snapshot.cost.total_tokens` |

### M3 · 上下文关联匹配度（R1 记为 N/A，仅 R2/R3 计算）

| 编号 | 分量 | 判定式 |
|---|---|---|
| C1 | 目标一致 | 本轮 `target.path` == 上轮 `target.path` → 1，否则 0 |
| C2 | 锚点复用率 | `|本轮锚点 ∩ 上轮锚点| / |本轮锚点|`；锚点用正则从 `body` 抽取：反引号路径、`path:line`、`<Component`、`attr="value"` |
| C3 | 历史未丢 | 上轮 `current_turn_id` 仍能在 `svc.list_turns` 结果中找到 → 1，否则 0 |

**关联度 = (C1 + C2 + C3) / 3 × 100%**

### M4 · 环境一致性（不达标则该轮作废）

每轮开始前采集并逐字节比对：`.env` 的 sha256、`settings.json` 的 sha256、配置摘要（`llm_provider` / `llm_model` / `api_mode` / `multi_model_routing` / `db_path`）、`project_root`、`session_id`（R2/R3 必须等于 R1）、进程 PID。

## 四、执行方案

### 新增文件（唯一）

`eval/multiturn/run_3rounds.py`

```python
"""三轮递进式关联测试：同一进程、同一会话、仅原句变化。"""

ROUNDS = [
    ("R1", "将当前项目中的前端页面中的管理员界面中的新增图书按钮改为红色。"),
    ("R2", "在上一轮的基础上，把这个按钮的红色改成橙色（warning），"
           "保留原有图标和尺寸，不要改动点击逻辑。"),
    ("R3", "沿用上一轮确定的这套配色与写法，同样应用到本页面的"
           "\u201c编辑\u201d按钮上，保持两处视觉一致。"),
]
PROJECT = r"D:\前端作业\实验二"
```

主流程：

1. `cfg = AppConfig(); cfg.validate()` → `svc = await build_default(cfg)`
2. 采集基线环境指纹（M4 的六个分量）
3. 逐轮循环：
   - `t0 = perf_counter()`
   - 采集并比对环境指纹，不一致 → 该轮标 `INVALID`，立即中止
   - `snapshot = await svc.optimize("local", PROJECT, sentence, request_id=f"{tag}-{uuid4().hex[:8]}", session_id=sid, locale="zh-CN")`
     - `sid` 首轮为 `None`，之后固定为 R1 返回的 `session_id`
   - 分支兜底：
     - `status == "ask"` → 用每个 `UnknownItem.key` 配 `best_guess`（空则用「按你的建议」）组成 `answers`，调 `svc.ask_followup("local", sid, answers, request_id=...)`，并标记 `asked=True`
     - `status == "guardrail"` → `svc.guardrail_confirm("local", sid, True, request_id=...)`，标记 `guardrail=True`
     - `status in {"abort"}` 或抛异常 → 记录错误，**停止后续轮次**
   - `elapsed = perf_counter() - t0`
   - 计算 M1 / M2 / M3（R1 的 M3 记 `N/A`）
   - **立即打印该轮三项指标**（满足「每轮完成后即时输出」）
   - 把该轮原始快照与指标追加进 `records`
4. 落盘 `eval/multiturn/result-2026-11-11.json`（审计留痕，非报告）
5. 打印汇总表（三轮指标并排）

### 变量控制

| 变量 | 处理 |
|---|---|
| 代码 | 不改任何源码 |
| 进程 | 全程单进程，不重启 |
| 配置 | 同一 `AppConfig` 实例 |
| 项目路径 | 三轮均为 `D:\前端作业\实验二` |
| 会话 | 三轮同一 `session_id` |
| 分支方式 | 不使用 `base_turn_id`（线性续接，非回滚分支） |
| 语言 | 固定 `zh-CN` |
| 唯一变化量 | `sentence` |

### 失败处理

| 情形 | 处理 |
|---|---|
| R1 失败 | 立即停止，在对话中报告错误码与堆栈摘要，不伪造后续数据 |
| R2/R3 失败 | 记录该轮失败，其余指标记 `N/A`，不重试（重试会污染耗时口径） |
| 目标选错 | A1 记 0，**不人工纠正**（纠正即引入干扰变量），继续跑完 |
| 环境指纹变化 | 该轮及后续作废，报告实际差异 |

## 五、假设与决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | 进程内调用而非 HTTP | 消除端口/进程/SSE 三类外部变量 |
| D2 | `user_id="local"` | 与 [`_USER_ID`](file:///d:/Works/DevPrompt%20AI/src/devprompt_ai/interfaces/api/routes.py#L56) 一致，会话在 UI 历史里可见可复核 |
| D3 | 准确率用预设清单规则评分 | 你选定；每项 0/1 可复现，不受主观影响 |
| D4 | M3 只在 R2/R3 计算 | R1 无前序上下文，定义上不适用 |
| D5 | 不重试失败轮次 | 重试会使耗时指标失真 |
| D6 | 落盘原始 JSON 但不出报告文件 | 「仅对话输出」针对报告；原始快照是「记录」要求的载体，也是复核依据 |
| D7 | 脚本放 `eval/multiturn/` | 与既有 `eval/recall/measure_ranking_ab.py` 同构，属工具而非交付物 |
