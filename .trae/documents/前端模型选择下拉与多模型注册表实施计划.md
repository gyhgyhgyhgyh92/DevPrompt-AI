## 一、Summary

将启动卡片中只读的模型名文本（[ConsoleInput.tsx](file:///d:/Works/DevPrompt%20AI/frontend/src/components/optimize/ConsoleInput.tsx#L100) 的 `console-input__model`）改造为**下拉选择框**：默认展示当前生效模型的完整名称，选项为多模型注册表中的全部条目，选中即经 `PUT /settings` 切换生效（整条生效：端点+密钥+模型 ID）。同时按裁定③把设置中心「模型服务」页改为**模型列表管理**（新增/编辑/删除/设为当前），使注册表可在界面维护。

**关键技术约束（沿用既有架构）**：`settings.json`（0600）为密钥唯一落盘处、响应恒脱敏、密钥不入库不进日志（MUST-19）；`AppConfig` 仍从 `model_service` 段取值 → **`harness/llm.py` 与 `config.py` 零改动**（激活时把所选条目镜像写入 `model_service`）。契约**不新增路径**（13 路径/16 操作不变），仅 `SettingsResponse`/`SettingsUpdate` 增字段（additive）。

**明确不做**：不新增独立端点；不改 `llm.py` 客户端缓存逻辑；不引入第三方依赖；不动超时/温度/max_tokens/决策层等全局参数语义（保留在原处）。

### 阶段 A · 后端：注册表存储（memory 层，纯函数）

**A1. `src/devprompt_ai/memory/settings_store.py`** 新增：
```python
_REGISTRY_KEY = "models"
_ACTIVE_KEY = "active_model_id"

def read_model_registry() -> dict[str, Any]:
    """读 settings.json 的模型注册表：{"models": [...], "active_model_id": str}；缺失返回空表。"""

def write_model_registry(models: list[dict[str, Any]], active_model_id: str | None) -> None:
    """整表写 models + active_model_id（None 不覆盖既有值）；与 write_model_settings 同一原子替换 + 0600。"""
```
- 复用现有 `_settings_file_path()` / `SettingsStoreError` / 原子 tempfile+replace+chmod 写法（抽出一个内部 `_rewrite_section` 或就地实现，避免重复）。
- 模块 docstring 补一句：注册表各条目的 api_key 与 model_service 同处 0600 文件（MUST-19 边界不变）。

**A2. `src/devprompt_ai/interfaces/api/schemas.py`** 新增：
```python
class ModelEntryView(BaseModel):
    """注册表条目的脱敏视图（F-604）：api_key 恒脱敏，is_active 标记当前生效项。"""
    id: str
    label: str
    provider: str
    base_url: str
    model_id: str
    api_key_masked: str
    is_active: bool

class ModelEntryUpdate(BaseModel):
    """PUT /settings models 段条目：id=None 为新增（后端生成）；api_key None/空=保留原值。"""
    id: str | None = None
    label: str | None = None
    provider: str | None = None
    base_url: str | None = None
    model_id: str | None = None
    api_key: str | None = None
```
- `SettingsResponse` += `models: list[ModelEntryView]`
- `SettingsUpdate` += `models: list[ModelEntryUpdate] | None = None`、`active_model_id: str | None = None`
- 字段**无默认空列表**（保持必填，避免生成类型含 `?`——沿用 `BrowseResponse` 处既有约定与注释理由）

### 阶段 B · 后端：服务层编排

**B1. `src/devprompt_ai/service.py`**
- 新增内部方法 `_registry_view(self) -> list[dict[str, Any]]`：读注册表 → 每项输出 `{id,label,provider,base_url,model_id,api_key_masked: mask_secret(...), is_active}`（`is_active` 判定来自 `active_model_id`，**纯数据比对非业务阈值**）。
- `get_settings()` 增 `"models": self._registry_view()`。
- `update_settings()` 增分支（在现有 model_service/process 处理之前或之后，保持互不干扰）：
  1. 若 `models` 非 None → **整表替换**：逐条解析；`id` 为空则生成（`"m-" + uuid.uuid4().hex[:8]`，标准库）；`api_key` 为空/None 时，若旧注册表存在同 `id` 条目则**沿用旧密钥**，否则视为未配置（存空串）；`label` 为空时按 `f"{provider} · {model_id}"` 派生。
  2. 若 `active_model_id` 非 None → 写入注册表激活位；**并从注册表取该条目，把 provider/base_url/api_key/model_id 镜像写入 `model_service`**（`write_model_settings`），再 `setattr(self._cfg, ...)` + `validate()` → 运行配置即时生效（整条生效，裁定⑤）。
  3. 注册表为空且无 active 时：不写 model_service（行为与现状一致，零回归）。
  4. 现有 `model_service` 段入参语义**完全保留**（其它调用方与旧测试不受影响）。
- `import uuid`（标准库，MUST-04 第 2 级）。
