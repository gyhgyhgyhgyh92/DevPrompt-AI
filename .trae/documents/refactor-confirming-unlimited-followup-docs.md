# CONFIRMING 机制重构 · 文档同步计划（无轮次上限的多轮自适应澄清）

> 日期：2026-10-06｜范围：**仅文档**，不动任何代码（用户指令）
> 性质：宪法 BREAKING 变更——突破 MUST-26「禁止无限追问 / MAX_FOLLOWUP_ROUNDS(2)」，由宪法所有者（用户）明确批准，按宪法附则记录批准人

## Summary

将反问机制从「固定 2 轮批量答复」彻底重构为「无预设轮数上限的多轮自适应澄清」。终止不再由轮次计数驱动，而由「具体未决事实是否耗尽 + 用户显式逃生 + 软护栏显式裁决」三元驱动（Cursor/TraeCode agentic clarification 最佳实践的落地形态）。本轮同步全部相关文档；代码实现归入阶段四 T4-4，随阶段四开工落地。

## 已定稿决策（用户 2026-10-06 批准）

| # | 决策 | 结论 |
|---|---|---|
| 1 | 终止机制 | **具体未知驱动 + 用户逃生**：每轮只提「具体未决事实」的追问；无具体未知 → 终止并直接输出；用户任一轮可说「直接生成」立即逃生进入生成；禁止泛化提问（「还需要更多信息吗」类） |
| 2 | 成本护栏 | **软护栏 + 显式询问**：单流程追问轮数 ≥10 或 LLM 成本超预算时，不静默终止，显式展示已澄清清单并询问「继续追问 / 直接生成」，用户选择后护栏计数清零继续 |
| 3 | 原「禁止 LLM 判断信息够不够」禁令 | **改写**：LLM 不自评信息充分性，只产出「具体未知项清单」——原禁令的动机（自我怀疑）由机制消除，而非放宽 |
| 4 | 原「综合置信度 ≥0.75」三判定 | 从**终止条件**降级为**输出档位依据**（与 MUST-28 不越级输出联动，语义不变） |
| 5 | 多轮澄清与档位 | 澄清轮次可提升信息完备度档位（A→B→C 路径保留，MUST-28 不变） |

## Proposed Changes（逐文档：改什么/为什么/怎么改）

### 1. `AGENTS.md`（宪法，BREAKING）
- **MUST-26 整节重写**，新结构：
  - 名称改为「反问由具体未知驱动，无预设轮数上限」
  - 提问条件：存在**具体未决事实**（探针 unknowns / 取证未决 / 研判缺口）→ 本轮批量提出，每问绑定未知项 + 当前最佳推断；无具体未知 → 直接输出
  - 终止条件（任一即止）：① 具体未知耗尽；② 用户任一轮显式选择「直接生成」（`followup.escaped`）；③ 软护栏触发且用户裁决「直接生成」
  - 软护栏：单流程追问轮数 ≥10（`FOLLOWUP_SOFT_ROUND_GUARD`）或 LLM 成本超 `FOLLOWUP_COST_BUDGET` → `followup.guardrail` 事件 + 显式询问，用户裁决后计数清零
