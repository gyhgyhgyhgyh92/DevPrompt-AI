# 前端本地文件夹选择器改造 · 实施计划

> 版本 v1.0 · 2026-10-13 · 依据用户指示 + 2 项澄清裁定（AskUserQuestion）
> 裁定：①同意新增后端端点弹系统原生对话框（浏览器沙箱禁读绝对路径）②校验强度=存在且为目录（不拒绝 UNC/映射盘）
> 宪法基线：AGENTS.md v1.2；最小改动原则；不引入任何新增依赖

## 一、摘要

将启动页「选择文件夹（可选）」控件改为「选择文件夹（本地）」：**移除手动输入路径文本框**，改为点击后由后端（运行于本机）弹出 **Windows 系统原生文件夹选择器**，用户图形化浏览选择后，前端显示所选文件夹并沿用既有校验与提交流程。全程仅允许真实存在的目录，无法输入远程路径或无效格式。

**关键约束（裁定依据）**：浏览器安全沙箱下，纯前端目录选择 API（`showDirectoryPicker`/`webkitdirectory`）只能获得文件夹**名称**，无法获得绝对路径；而 `POST /optimize` 需要绝对路径定位项目 → 必须由本机后端弹原生对话框。

## 三、方案设计（决策完备）

### 交互流程（改造后）

```
用户点击「选择文件夹（本地）」
  → 前端 POST /api/v1/project/pick（按钮禁用防重复，MUST-15）
  → 后端 pwsh -STA 弹 Windows 原生「浏览文件夹」对话框（仅能选目录）
  → 用户选定 → 返回绝对路径 → 前端显示 basename（tooltip 全路径）→ 异步 scan 复校验
  → 用户取消 → 返回空串 → 前端保持原状、不报错
```

**② [service.py](file:///d:/Works/DevPrompt%20AI/src/devprompt_ai/service.py)** 新增方法（模块顶部 import `pick_folder_dialog`，与 harness.process 既有导入惯例一致）：

```python
async def pick_project_folder(self) -> str:
    """系统原生目录选择（POST /project/pick）：返回绝对路径；取消空串；非目录 2001（MUST-20）。"""
    path = await pick_folder_dialog()
    if path == "":
        return ""
    if not await asyncio.to_thread(os.path.isdir, path):
        raise RetrievalError("所选路径不是有效目录（请重新选择）", code=2001)  # 不回传路径本体（MUST-19）
    return path
```

## 四、假设与决策

1. **同机假设**：后端与浏览器在同一台机器（本工具定位本地运行：SQLite/符号表均为本地），对话框在用户桌面弹出
2. **平台**：实现 Windows（用户环境+PW7）；非 Windows 抛明确错误（未实现 macOS/Linux，按需后续）
3. **取消语义**：空串成功响应（非错误）；前端保持原选择
4. **校验强度**：存在且为目录（用户裁定）；不拒绝 UNC/映射盘
5. **超时**：后端 300s / 前端 310s；超时后端的 `ProcessTimeoutError` 由既有 app.py 映射路径自然上抛
6. **错误消息不回传路径本体**（MUST-19）
7. **保留 basename + tooltip 展示**，不新增只读全路径行（最小改动；如你在审阅时想要全路径可见行，请指出）
8. **不引入任何新依赖**：`pwsh` 为本机既有工具；缺失时 `run_command` 给出 `DPROMPT_PWSH_PATH` 配置指引
