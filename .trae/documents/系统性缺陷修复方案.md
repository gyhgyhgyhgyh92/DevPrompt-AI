## 二、改动方案

### A. 路径穿越防护（缺陷 1）

**新增** `src/devprompt_ai/domain/retrieval/paths.py`（纯函数、零 I/O，MUST-06 允许）：

```python
def safe_join(root: str, rel: str) -> str:
    """把仓库相对路径拼到根上并规范化；越界返回空串（调用方按「不存在」处理）。

    拒绝三类：绝对路径 / 盘符前缀 / 规范化后逃逸出 root。
    root 为空时，拒绝以 .. 开头的相对路径。
    """
```

**接线三处**：
1. `domain/retrieval/locate.py` 的 `_fs`（L223-224）→ 改调 `safe_join`；返回空串时不读文件（`text=""`、`test_paths=[]`、`excerpt=""`、跳过令牌探测）。
2. `domain/retrieval/facts.py` 的 `_fs`（L95-96）→ 同上；空串时 `exists` 传空串，结果为 False。
3. `service._probe_anchor`（L2620-2630）→ 用 `safe_join` 拼路径；空串直接返回 `False`（越界锚点判「明确无效」，符合交付门语义）。
4. `service._refresh_inherited_evidence`（L988-990）→ `target.path` 不安全时直接 `return`，记一次 `evidence.unsafe_target_path` 日志。

**为什么这样做**：`rel` 目前来自 ctags 输出，正常仓库不会越界；但畸形仓库可让符号表产出 `../../` 路径。硬拒绝而非「规范化后放行」，因为规范化会把越界请求偷偷改写成合法路径，掩盖上游异常。

**测试**：新增 `tests/domain/retrieval/test_paths.py`，5 例：正常相对路径、含 `..`、绝对路径、Windows 盘符、`root=""` 时的 `..`。

### C. 取证口径扩展（缺陷 4、5）

#### C1 · `has_state_styles` 对组件库项目判「不适用」

`domain/retrieval/facts.py`：

- 新增常量 `_UI_LIB_SIGNALS = ("from 'antd'", 'from "antd"', "@mui/material", "element-plus", "naive-ui", "@chakra-ui")`
- 在 `asyncio.gather` 里新增一次 `reader.read(_fs(path))`（与其它取证并发，不增加串行 RTT）
- 判定顺序：
  1. 目标文件命中 `:hover/:focus/:active` → `passed=True`（现状不变）
  2. 未命中且文件从已知 UI 库导入 → `applicable=False`，evidence 记 `ui_lib=<name>`
  3. 其余 → `passed=False`（现状不变）

**影响面（如实告知）**：AntD 项目的适用项从 7 项变为 6 项，`is_evidence_complete` 的分母随之变化；`facts` 快照里该条 `applicable` 变为 false，前端展示会少一条。

#### C2 · 令牌探测扩面

`domain/retrieval/locate.py`：

```python
_TOKEN_PROBE_PATTERNS = (
    r"color(?:Error|Primary|Warning|Success|Info|Link)\s*:",   # 保留：AntD 主题键
    r"--[A-Za-z][\w-]*\s*:",                                    # 新增：任意 CSS 自定义属性
    r"(?:brand|theme|bg|text|border)[A-Z][A-Za-z0-9]*\s*:",     # 新增：常见主题命名族

_TOKEN_PROBE_GLOB = "*.{ts,tsx,js,jsx,vue,svelte,css,less,scss}"
```

**测试**：locate 加一例 `.vue` 文件 + `--brand-500` 能探到；facts 加一例 AntD 导入 → `has_state_styles.applicable is False`。

### D. `file` 断言假阴性（缺陷 6）

`service._audit_claims`（L2504-2519）在 `validate_claims` 之前：

```
对 draft.claims 里 kind == "file" 的 target（去重、上限 5 个）逐个 reader.exists(root/target)
存在的目标追加 "file=<target>" 到 evidence_text
```

**为什么这样做**：现状只能核对「片段或令牌里出现过的路径」，引用工具函数/父组件时必然判未覆盖。一次有界 `exists`（≤5 次）即可消除，且不改变 `match_claims` 的判定逻辑。

**测试**：构造一条引用第三个真实文件的 `file` 断言，断言覆盖率由未覆盖变为已覆盖。

## 四、假设与决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | 路径越界「硬拒绝」而非「规范化放行」 | 放行会掩盖上游异常；拒绝后表现为「该文件不存在」，与既有失败路径一致 |
| D2 | `has_state_styles` 用「不适用」而非「通过」 | 直接判通过等于伪造证据；`applicable=False` 是既有机制（后端文件已这样处理） |
| D3 | 令牌 pattern 放宽但保留相关性排序 | 宽 pattern 会引入噪声，靠现有词元排序 + 上限 8 控制 |
| D4 | `file` 断言最多核 5 个路径 | 防止模型声明几十条路径导致每轮几十次 stat |
| D5 | 实施真源文档只加注不改写 | 历史台账不可篡改 |
| D6 | 不引入新配置项 | 所有阈值写成模块常量，避免配置面扩张（与 MUST-10 配置单一一致） |
